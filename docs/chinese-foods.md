# 中式早餐与包点扩库

以下记录0.9.2的第一轮包点扩库；0.9.3已进一步增加食品并补译名称，当前数量与教程见[第二轮中文化扩库](food-localization.md)。

这次针对“菜包、肉包搜不到”补覆盖，而不是继续堆同一种食物的相似版本。新增175条TFDA成品参考、10个可调包子配方。现在原始参考共5,850条，合并近似项后可选5,748条，另有70个可调配方和1,055款OFF包装参考。此数量包含做法变体，不表示相同数量的独立中式菜品。

## 怎么选

饮食 → 手动添加 → 选食物 → 搜索“菜包”或“肉包”；也可以切换“主食”分类。输入“肉包”时“鲜肉包”排在前面，不会因字面子串而找到“无肉包子”。

新配方包括菜包、香菇青菜包、鲜肉包、菜肉包、香菇肉包、牛肉包、鸡肉包、叉烧包、豆沙包、芝麻包。其他成品参考包括白馒头、黑糖馒头、花卷、小笼包、烧饼、油条、葱油饼、韭菜盒子、水煎包、锅贴、肉粽、饭团及糕点等。

填整份可食重量（g）；没有称重可保留AI逐项估计，但不把“一只包子”固定为100g，也不从数据库的样本单位重量默认出摄入量。照片识别出多种食物时分别匹配名称和重量，不把包子再展开成面皮、肉、菜三条饮食记录。

## 为什么包子采用可调配方

原库只有USDA `Bao bun`（未注明馅料）和 `Bao bun, no meat`（无肉）。无肉不表示青菜馅，未注明馅料也不表示鲜猪肉，因此这些旧条目及其数值继续保留原含义。

TFDA公开数据有冷冻猪肉包、冷冻素菜包样本，不能直接把冷冻重量基准改成刚蒸好包子的基准。本轮没有导入这些冷冻样本。应用为常见蒸包提出了明确的**参考配比假设**：

- 面皮：TFDA白馒头样本近似蒸熟面皮，编号`R2400201`，每100g为248 kcal、蛋白质8.1g、脂肪1.2g、碳水51.3g。
- 馅料：使用对应已熟肉、菜、豆等参考；猪肉、鸡肉的不同烹饪方式仍可能有水分差异，说明里注明近似。
- 全部配料以最终可食重量相加，基准为100g成品。没有把生面粉或生肉的投料重量直接当熟包重量。
- 示例菜包：65g熟面皮近似、30g熟大白菜、5g额外实际摄入油。这只是可编辑情景，不是数据库的“菜包标准配方”。
- 有独立加油配料时沿用已有少油／普通／多油区间，中档和区间中值记账；肉本身脂肪只在肉中计算一次。没有可靠区间的条目不编造上下限。

用户可以调整配料克数、皮馅比例、糖油和确定的营养数值。每餐保存配料、营养、来源、假设快照；以后扩库或调整参考配比不会重算旧记录。数据库样本和应用配方都不能代表某一家包子店的实测热量。

## 数据和许可怎么核实

来源是[TFDA食品营养成分官方数据集8543](https://data.gov.tw/dataset/8543)，页面标示免费，许可为[政府资料开放授权条款第1版](https://data.gov.tw/license)，允许在遵守署名等条款时再利用。

下载入口是`https://data.fda.gov.tw/data/opendata/export/20/json`，返回**ZIP，不是直接JSON**。2026-10-19下载压缩包4,587,490 bytes，SHA-256为`755d2f0e4a7c1fe80ac0636863117e376773c9342cfd68e7b05e67d81e3c6064`；解压后230,152行、2,213个样本。每条营养素各一行，需要按“整合编号”分组，读取“每100克含量”而非“每单位重含量”。

本轮白名单选取常见成品，另选取糕点类成品；排除生料、冷冻／冷藏半成品、冲泡粉和补充剂。读热量的kcal、粗蛋白／粗脂肪／总碳水的g，保留原数值；缺失不补0。其余微量营养素不在本轮界面中使用。

原始选中营养行、原文、样本数、单位和文件校验值保存在`packages/shared/data/tfda-chinese-source.json`。数据许可见`CHINESE-FOODS-LICENSE.md`；应用设置页和随APK附带的`licenses/tfda-foods.txt`均有署名。2026-10-19是快照日期，不是所有食物的采样年份；官方未提供单条发布日期的，不编造年份。

## 开发时如何重新导入

先安装依赖、构建shared（导入工具读取现有USDA条目来避开重名）：

```powershell
npm install
npm run build -w @shike/shared
node scripts/import-chinese-foods.mjs
npm run build -w @shike/shared
node scripts/report-food-curation.mjs
```

没有参数时从仓库中的选中原始行重现，结果应逐字节一致，不请求上游。首次下载新版官方ZIP后解压，再运行：

```powershell
node scripts/import-chinese-foods.mjs --source .data-cache/tfda/official/20_5.json
```

白名单在导入脚本里，名称通过固定版本opencc-js转换，常见别名由人工补充。重新下载新版数据时需同时更新脚本的快照日期、复核样本状态与许可，再运行测试，不能将历史快照批量替换。构建、运行和手机使用都不爬取这个API，不需要营养数据库Key。

## 验证

覆盖官方营养行一致性、缺失与单位、来源编号、175项的样本状态、包子熟重缩放、不重复计数、旧备份格式、搜索优先级、肉包与无肉区别、多食物分别保留重量。浏览器场景检查手机视口、Chrome桌面、Edge上的选取、保存、刷新和备份来源。

截图`docs/screenshots/chinese-foods-mobile.png`来自本地测试食物选择器。APK继续包含0.9.1的CameraX实现；本次扩库没有完成OPPO Find X9光学清晰度真机验收。
