## 1. 测试包如何工作

使用 [Capacitor 8](https://capacitorjs.com/docs/android) 的本地资源模式，WebView 从 APK 内置的 `https://localhost` 加载页面、图标和食物库。打开记录不等待网络探测。默认在设置添加自己的模型配置即可联网识别，支持移动数据，电脑可关闭。“连接食刻服务”模式才需要 HTTPS 后端与内测访问码。[手机多模型教学](personal-models.md) · [可选 FC 部署](cloud-deployment.md)

`packages/web/capacitor.config.ts` 中只有联调时设置 `server.url` / `cleartext`。Capacitor 官方明确该配置面向开发，不能作为正式发行方案。[配置说明](https://capacitorjs.com/docs/config)

显式 `--preview` 才使用原局域网开发模式，该模式仍需要电脑在线。默认独立包不写入 `server.url` 或 `cleartext`，保持 HTTPS 本地来源。当前仍是 debug 签名内测包，不用于应用商店发布。

**从旧局域网版升级前先导出 JSON 到手机文件，再安装和恢复。** 两种来源的 IndexedDB 隔离，不会自动迁移，不要在备份前卸载或清数据。

## 2. 本机前置条件

- Node.js 24、项目依赖 `npm install`。
- JDK 21，`JAVA_HOME` 指向该 JDK；构建流程固定已验证版本，避免更新的 JDK 与 Gradle 不兼容。
- Android SDK：`platforms;android-36`、`build-tools;36.0.0`；USB 安装还需要 `platform-tools`。`ANDROID_HOME` 或 `ANDROID_SDK_ROOT` 指向 SDK 根目录。
- 可通过 [Android Studio / SDK Manager](https://developer.android.com/studio) 安装上述工具，并按官方要求接受相应 SDK 许可。

本工作区已将必要工具下载、按官方 SHA-256 校验，并放在 `.data-cache/android/`。构建脚本在没有显式环境变量时自动查找此缓存；全新克隆需要自行配置 SDK/JDK。Gradle Wrapper 使用官方 8.14.3 bin 分发和固定 SHA-256，首次构建需要联网下载 Gradle 与 Maven 依赖。

不会修改系统全局环境变量，Gradle 缓存、Java 用户目录和调试签名都放在项目缓存中。工作区有中文路径，因此 Gradle 显式允许非 ASCII 项目路径；当前使用 Java/Android 资源，不包含 NDK 编译。

## 3. 构建与手机安装

独立构建不需要服务运行：

```powershell
npm run android:apk
```

如需要继续使用局域网联调模式：

```powershell
npm run dev:lan
# 另一个终端：
npm run android:apk -- --preview
# 多网卡或需要明确指定地址时：
npm run android:apk -- --url http://电脑当前局域网IP:5180/
```

脚本构建前端、同步 Capacitor 插件、执行 Gradle `assembleDebug` 并验证 APK 签名。独立包输出 `artifacts/android/shike.apk`，相邻 JSON 包含模式、文件大小和 SHA-256；只有联调模式先检查电脑 `/api/health`，并输出 `shike-preview.apk`。

独立 App 的页面产物单独写入 `packages/web/dist-android`，不会覆盖普通网页的 `dist`。构建 APK 后，已有的 `npm start` 网页产物仍使用同源后端；两个构建目录都不提交 Git。

运行 `npm run dev:lan` 时，手机可打开 `http://电脑IP:5180/downloads/shike.apk` 下载独立包，下载后不再依赖电脑。旧联调包对应 `/downloads/shike-preview.apk`。下载入口仅提供这两个固定文件，不开放任意本机路径。也可通过 USB：

```powershell
adb install -r artifacts/android/shike.apk
```

USB 方式需要启用开发者选项与 USB 调试，并确认电脑授权。同一缓存调试签名才能覆盖安装，换签名时先备份。独立包不随电脑 IP 变化；联调包换电脑 IP 时仍需重新构建。

## 4. 数据与功能边界

- App 的 WebView 和手机浏览器、电脑浏览器各自保存 IndexedDB 数据；默认不云同步，也不自动读取已有浏览器记录。
- Android 系统自动备份关闭，明确由用户使用 JSON 导出与恢复；卸载 App 或清除 App 数据会删除本地记录。
- 手机与APK默认进入全屏实时取景页；Android首次申请相机权限，不申请麦克风。LAN HTTP网页无法实时预览时，可用系统相机／选图回退。真实手机的方向、补光、系统权限、照片格式及返回流程需要逐项实测。
- 安卓导出备份通过 Filesystem 将 JSON 写入 App 缓存，再打开系统分享菜单，选择保存位置或分享给自己的工具；不依赖 WebView 的 blob 下载，也不申请整个手机的存储权限。缓存文件不是外部永久备份，要在系统菜单完成保存。导入仍通过系统文件选择器并预览确认后替换。
- AI 服务不可达时保留本地功能和草稿，在设置中重新连接，不会白屏。应用内置资源异常才显示本地重新打开页面；局域网 HTTP 的 UUID 回退继续有效。
- 移除了“我已核对食物和重量”的强制复选框：识别后可编辑并直接点“保存记录”，保留估算、模拟来源与缺失值提示。

## 5. 真机检查清单

安装后验证启动与重试、相册选择、相机返回、图片压缩、多食物识别、逐项份量编辑和直接保存。随后关闭 App 重开，检查历史、体重、目标、备份导出与恢复；检查刘海屏、系统返回键和键盘是否遮挡保存按钮。真实 AI 仍可能限流或网络失败，要确认错误提示不会清掉草稿。

APK 构建、验签和浏览器手机视口通过，并不等于 Android 真机上的相机、分享、安装权限和 WebView 交互都已通过；未连接设备时需在收到 APK 的手机上完成上述项目。
