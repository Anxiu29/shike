# 对话自动匹配与营养估算修复计划

> **For agentic workers:** Use superpowers:executing-plans inline; follow test-driven-development and verification-before-completion.

**Goal:** “一个鸡蛋饼”等自然描述自动获得可核对的重量与热量，而非停在手填；已有食品优先复用。

**Architecture:** 对话请求携带最多24个相关本地候选，模型可返回候选ID；ID只能在本次提供的集合中采用。未匹配食品允许返回每100g或100mL营养范围与假设，程序计算中值、热量和来源快照。在线模型漏掉必要资料时仅自动补问一次，失败保留原草稿并说明，离线/Mock不触发在线补问。

**Tech Stack:** Vue、TypeScript、Zod、Vitest、Playwright、Capacitor。

**Spec:** 本文件设计与已复现实例；用户已要求用AI估重量，本次明确反馈聊天未算热量、已有食品未采用。

## 已核实的问题

- Qwen3.7-flash 对“一个鸡蛋饼”返回1个、AI估150g；原契约禁止营养粗估，精确匹配失败后无法计算。
- “鸡蛋饼”不是库中精确名称；“蛋饼或炒蛋”不能不经核对等同中式面糊饼。
- 常用食品快照未接入聊天，包装别名/候选也未交给模型。
- 详细编辑汇总把全部未知的已知合计0显示成约0kcal。

## 约束与验收

- 不覆盖已有库营养，不把不同品牌/生熟/糖油的相近名称静默当成同一食物。
- 输入的数量、克数和毫升数优先；补问不能改写这些数值。
- 区分质量与容量；每100g数据不可当每100mL。
- 估计范围与假设保留到餐次快照；0是明确零值，未知保持null。
- 不后台自动切换模型，不改历史餐次；仅估算不记餐。

- [x] 本地候选检索、来源优先、自动补问与失败保护。
- [x] 聊天展示范围/来源、编辑页未知不显示0、端侧契约与额度输出长度。
