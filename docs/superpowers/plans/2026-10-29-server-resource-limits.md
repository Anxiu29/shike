# 服务端资源限制优化

> 按用户“还有什么要优化，有的话开始优化”的授权，在当前工作区执行；保留上一轮尚未提交的前端修改。

**Goal:** 异常上游响应及时停止读取；图片解码与模型调用共用并发上限；无效图片不计入每日调用额度。

**Architecture:** 增加有界文本读取工具，AI正常响应限1MiB、GLM错误响应限16KiB、OFF商品查询限256KiB，全部以实际读取的字节为准。RecognitionLimiter分离占用槽位和每日计数，图片验证通过后才计数，所有路径finally释放槽位。

**Approaches:** 选择流式读取而不是提高完整缓冲后的阈值；选择复用现有并发器而不是另加一套互不关联的解码并发数。保留已有错误码、超时与显式模型选择，不增加依赖、部署或APK生成。

## Review Focus

- 没有Content-Length、头部长度不实、中文多字节和分块UTF-8仍按真实字节限量。
- 超限/超时/错误HTTP响应不会继续保留未读响应流；取消失败不覆盖业务错误或阻塞返回。
- 空响应、JSON异常保持已有安全错误码，不回显原文或密钥。
- 图片解码与文字调用共同受并发上限约束；无效图片不扣每日额度。
- 验证失败、上游失败、日额度耗尽和请求成功均释放槽位。
