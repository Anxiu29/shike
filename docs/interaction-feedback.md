# 操作反馈检查

本轮按页面与操作路径核查，区别导航、筛选等立即可见的变化，以及收藏、保存、删除、连接等需要等待结果的操作。不会给每个导航按钮都增加成功提示。

- 常用食物库：星标/取消星标显示所操作食物名称，数据库提交后才改变状态；进行中显示转圈并阻止重复提交。保存失败保持原状态并允许重试。移除与撤销继续保留，并让全局提示出现在当前弹窗内。
- 食品选择器：收藏提示包含具体名称，正在操作的星形按钮显示加载状态，已收藏有填充图标与底色，保留`aria-pressed`和错误说明。
- 餐次：保存已有等待状态与失败草稿保护；补上重复保存防护。删除有等待状态，成功后可撤销，照片随记录一起恢复。打开编辑、复用、查看图片均有对应可见界面。
- 模型：切换时显示进行中；切换成功显示文字反馈；失败还原原选择。原生设置重新读取实际状态后才报告切换成功。原有测试/保存/删除/连接的操作状态、错误和敏感信息保护继续保留，连接补上重复提交防护。
- 设置：备份导出、读取、恢复分别显示等待文字，处理时禁用重复操作和关闭入口。个人估算删除显示对应条目的加载状态，错误在当前弹窗内可见。
- 包装库：保留条码查询、相片读码、保存、移除的加载和结果说明；新增全局提示以避免滚动后看不到结果，保存按钮显示进行中，避免旧错误掩盖新成功。
- 体重与目标：补上目标保存、删除的等待状态与重复提交防护，保存期间禁用对应输入，避免结果返回时清掉新输入。目标页、饮水和运动已有提交状态、结果与撤销路径，纳入浏览器回归。
- 取景、日历、日期选择、份量、分组、主导航：保留现有选中/展开/页面变化与加载、错误提示。统一可用按钮的按压阴影和键盘焦点；按压不使用会改变包含块的滤镜，以免破坏食物卡片的整卡详情入口。

原全局toast在原生`dialog.showModal()`下方，即使z-index很大仍被顶层遮挡。`AppToast`随弹窗开关移动到当前最上层dialog内部，进入弹窗焦点循环；普通页面仍放在body。弹窗内提示占独立布局行，避免盖住保存、加入或关闭按钮。长食物名称可换行，关闭与撤销保留可点击空间。

回归不只断言文字存在，还通过`elementFromPoint`检查提示位于实际点击层，点击撤销验证数据恢复；通过模拟慢存储、QuotaExceededError检查忙碌状态、重复点击与失败不误报成功。对应`PersonalFoodFeedback.test.ts`、`meal-photos-feedback.spec.ts`及现有`interaction`、`personal-foods`、`food-library`、`settings`、`personal-models`、`packaged-food`等浏览器用例。

本版验证：490项单元/接口测试、20项原生策略检查；Chrome手机/桌面与Edge覆盖156项源页面场景，最终独立APK资源另验证15项场景。真实Android安装、相机硬件、软键盘与系统分享仍需真机验收。
