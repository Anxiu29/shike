一个中文、手机优先的 AI 饮食记录 Web App。普通餐食拍照识别食物与份量，有可靠数据库或参考配方时优先查库；缺库时使用带假设的 AI 营养估算。糖、用油等提供三个参考情景，默认普通档，以区间中值记账；也可以输入确定数值。包装食品优先读取营养表，再按实际摄入量换算。记录保存在当前浏览器的 IndexedDB 中。

## 本地运行

需要 Node.js 24 LTS 或更新的受支持版本、npm。

```powershell
npm install
# 已有 .env 时不要覆盖；仅首次配置执行下面一行。
Copy-Item .env.example .env
npm run dev
```

启动后会自动使用系统默认浏览器打开 <http://127.0.0.1:5180>。前端通过 Vite 代理访问本机 3001 端口的后端。未配置所选模型的密钥时，默认进入明确标识的 Mock 模式，仍可完整测试识别、编辑与保存。

本项目的 npm 缓存位于 `.npm-cache`，不会修改系统 npm 设置。首次安装需要访问 npm 官方仓库。

### 手机查看

电脑与手机连接同一 Wi-Fi，先停止原来的开发服务，再运行 `npm run dev:lan`。电脑会自动用默认浏览器打开局域网地址；等前后端启动后，在手机系统浏览器打开终端打印的同一地址（例如 `http://192.168.1.10:5180/`）。命令自动配置本次运行的精确页面来源，后端仍只监听电脑本机，不修改 `.env`。普通 `npm run dev` 保持仅本机访问。

手机与电脑的数据各自保存在当前浏览器，不会自动同步；可用 JSON 备份迁移。网卡选择、防火墙和相机入口说明见 [手机联调教学](docs/mobile-testing.md)。

### 安卓测试 APK

执行 `npm run android:apk`，默认生成内置完整页面的独立测试包 `artifacts/android/shike.apk`，无需开发服务在线即可构建。需要 JDK 21、Android SDK 36 和 build-tools 36.0.0；本工作区可使用已忽略的项目缓存工具链。运行 `npm run dev:lan` 时可从 `/downloads/shike.apk` 下载到手机，仅下载这一步需要访问电脑。[安卓构建与真机测试教学](docs/android-app.md)

独立APK支持手机自配Key：设置 → 我的AI模型 → 添加模型配置 → 测试并保存。可保存多组百炼／硅基流动／OpenRouter／Gemini／GLM Key与模型并手动选用，无需电脑、自建服务器或同一Wi-Fi；AI仍需联网，费用与免费条件以提供商为准。Key在安卓私有空间加密保存，不进入记录备份。食物库、饮食与体重可离线使用。[手机多模型配置与调用教学](docs/personal-models.md)

自建云端连接入口暂时关闭，旧保存地址不会自动使用；独立 APK 默认手机直连，普通网页使用本机 Node。FC 代码和文件保留供以后启用，本次不部署云资源。[保留的部署方案](docs/cloud-deployment.md)

**升级前先导出 JSON 备份，再覆盖安装**：独立版来源与旧电脑 IP 的存储隔离，旧局域网版需要恢复备份。APK使用调试签名，包名不变，当前为0.11.6-test（versionCode 29），包含一Key多模型、申请教程、餐次拍照快捷入口、全屏取景、首页下拉跟手月历、日期摄入比例、最近／常吃、整餐复用、个人常用食物库、资料同步、返回导航和此前CameraX修复；请勿在备份前卸载或清数据。保留 `npm run android:apk -- --preview` 显式构建旧联调方式。安卓导出仍走系统分享菜单，尚未完成真机相机或商店发行验收。

## 配置 AI

根目录 `.env` **只由服务端读取**。不要给密钥添加 `VITE_` 前缀，不要在前端代码、截图、Git 提交或教学笔记中写入真实密钥。

```dotenv
AI_PROVIDER=gemini
AI_MODE=auto
GEMINI_API_KEY=在本机填入你的密钥
ZHIPU_API_KEY=
DASHSCOPE_API_KEY=
QWEN_MODEL=qwen3.7-flash
```

新项目开发默认模型为 `gemini-3.5-flash-lite`，也可以选择配置好的百炼等模型。AI 不限制必须免费，费用以提供商控制台为准；有免费层级不代表所有项目都免费。应用不会自动切换模型或开通计费。

切换智谱：将 `AI_PROVIDER` 改为 `glm`，配置 `ZHIPU_API_KEY`，重启后端。模型固定为 `glm-4.6v-flash`，使用普通 API，不使用 Coding Plan 的套餐端点。

切换国内百炼默认模型：将 `AI_PROVIDER` 改为 `qwen`，配置北京区通用 `DASHSCOPE_API_KEY`，`QWEN_MODEL=qwen3.7-flash`，重启后端。配置过 Key 的白名单型号会出现在识别面板，网页可手动选择 `qwen3.7-flash`、`qwen3.8-flash`、`qwen3.7-plus` 等已开放选项；服务端仍校验列表，密钥不返回网页。没有配置 Key 的提供商不出现在额外选项中；`AI_MODE=mock` 只提供模拟。所有模型共用校验、限流和记录格式，不自动改选或轮换 Key。HTTP 200 本身不能证明本次免费。

`AI_MODE=mock` 强制模拟；`auto` 缺少所选模型密钥时模拟；`live` 要求密钥存在。真实调用失败会显示错误，不能把模拟结果冒充真实识别。模拟记录保存后仍带有标识，当日汇总也会提示。

2026-10-14 的最小调用测试中，Gemini 的视觉、非食物拒识和结构化输出均成功；GLM 两次返回 429/1305 服务过载。这些结果不是餐食重量准确率承诺。

详见 [AI 模型调用教学](docs/ai-models.md) 和 [完整开发教学](docs/development-guide.md)。

国内模型的真实对照与价格核验见 [国内视觉模型选择](docs/domestic-models.md)：本次已用配置好的百炼 Key 对照三个 Qwen 型号和 Gemini。Qwen3.7-Flash 与 Gemini 通过公开餐食和非食物两张图；Qwen3.8-Flash 的餐食结构校验失败，Qwen3.7-Plus 的餐食超时。当前工作区已切换 Qwen3.7-Flash；新克隆项目仍沿用 `.env.example` 的 Gemini 默认配置。按用户决定，不再继续请求一直 429 的 GLM。

## 使用与数据

- 饮食页可以拍照、上传、手动记录，修改食物名称、可食重量和每100g营养值，再选择日期及餐次保存。点击“选择食物”打开弹窗：**5,880项去重食物 + 90个可调配方**按类浏览。原始数据含472条USDA SR Legacy、5,203条USDA FNDDS 2021–2023、307条TFDA参考；含不同做法与配料版本，不等于这么多种独立中国菜。中文优先展示，支持别名、旧名称、原文和配料检索；包装参考有中文补译或明确类别提示，仍显示原名供核对。列表每次显示60项。顶部本地推荐与识别名称和可见配料相近的食物，不增加AI请求，点击候选后才更换记录。照片识别与AI营养粗估合并为一次模型请求。
- 计算顺序为基础食物／参考配方、已确认的个人估算条目、本次 AI 粗估。无依据时仍显示待补充，不把未知当零。AI 不确定名称时仍拒绝编造食物。
- 默认浏览熟食和即食食物，隐藏生肉、生蛋及待烹调干料；水果、生菜和黄瓜保留。可勾选“包含生重／干重食材”查看全部，已保存的生重记录不受影响。
- 一张照片可返回多种食物，逐项自动匹配食物库／参考配方，并带入各自的可食重量；总览可查看所有项并跳到对应编辑卡片。“一碗米饭”等量词可在本地简化后匹配，不额外请求模型。混合菜不再重复累计其可见配料；模型无法估重时，应用先补带标记的常见份量，可按实测修改，确认后保存。
- 热量、营养、重量、区间及输入框最多显示两位小数，不补尾零。内部计算和历史快照保留完整精度，用户主动输入的确定值最多两位。
- 旧个人库只有单值，或其普通档缺少热量时，本次识别提供的有效热量三档会优先采用。确认保存后升级原库条目并保留 ID；旧餐食仍使用原来的数值快照。不会给旧单值凭空补出范围。
- 新 AI 估算提供低／中／高三档，按食物显示甜度与稀稠、用油或一般情景。默认中档，再取该档区间的算术中值。参考配方的油档在原配料中替换油量，不另加一份油。确定的包装营养值或实际配料可手填，替代这一条范围估算。
- 区间统一按每 100 g 保存，按食物重量换算整份。例如参考粥普通档 60～90 kcal/100 g，300 g 的区间为 180～270 kcal，记账中值为 225 kcal。这是应用参考情景，不是所有粥的标准，更不是模型测量精度。历史保存当时的档位；下一次新识别同名食物重新默认普通档。
- 真实识别的 AI 缺库条目只有在确认保存后，才与餐食一同写入个人估算库；未保存的草稿和 Mock 数据不会污染这份库。库里的数值始终标注估算，不会加入 USDA 数据或共享给别人。
- 体重页每天记录一次体重，支持修改、删除和设置目标。
- 设置页支持 JSON 导出与完整恢复。当前备份版本10，兼容版本1～9；保留个人食品与收藏、日常单位估重、餐食标签与摄入份量、个人资料、目标快照、运动、饮水和个人估算库。恢复前校验并显示数量，确认后事务性替换。
- 浏览器清理、隐私模式、换设备、换浏览器或换网址会影响本地数据。`127.0.0.1` 与 `localhost`、不同端口也是不同存储空间；定期导出备份。
- 图片只用于本次识别，应用不把照片保存进 IndexedDB、上传目录或日志。Gemini 使用内联图片及 `store:false`；免费服务仍可能用输入和输出改进 Google 产品。

基础营养数据来自 [USDA FoodData Central](https://fdc.nal.usda.gov/)，其数据为公共领域／CC0。中文名称为应用整理的别名，参考配方为食刻的计算假设，不能视为中国标准菜品数据。AI 补充的数值只是根据常见做法的粗估：合法范围检查不代表真实准确，粥的含水量、用糖和用油等差异需确认。来源及换算规则见 [营养数据说明](docs/nutrition-data.md)。无法粗估的数据仍保留为空，汇总显示已知部分。

## 后续部署

第一版面向本地运行。未来可部署到提供 Node.js 的服务器或容器，由 HTTPS 反向代理提供同源访问。密钥放在平台环境变量；前端静态构建和服务端一起部署。免费托管能否持续免费、地域连通性、休眠和请求额度需在部署时重新核实。

公网部署已加入访问码换取 7 天令牌、精确 CORS 和 OSS 原子追加的共享日限额；`APP_PUBLIC_MODE=true` 缺少保护配置会拒绝启动。额度故障阻止模型调用，不退回内存。分钟限频仍在实例内，FC 初期须限制最大实例数 1，且不盲信客户端代理头。部署文件已准备；本次未运行 Docker、未部署云资源，也未做安卓真机验收，Linux 镜像与 FC/OSS 真实权限仍需部署时验证。[部署步骤与费用边界](docs/cloud-deployment.md)

此工作区的初始本地 Git 历史曾包含旧智谱密钥；现已清理历史及敏感对象，但 Git 清理不会撤销密钥，旧密钥仍须在智谱控制台撤销；旧仓库副本也需处理。[密钥清理原则](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)

本版没有账号、收费和云同步。图片份量、混合菜的油与酱汁都可能有较大误差，所有热量为估算值。

独立版另外验证：实际 APK 解包资源在浏览器禁网、本地资源模拟下可启动，手动饮食、体重和目标保存后刷新仍可恢复，未尝试访问电脑或外部网络。APK 已验签，下载文件哈希与本地一致，内置资源扫描未发现本机模型 Key 或内测凭证；这不代替安卓真机、FC 和 OSS 的真实部署验收。
