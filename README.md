# 食刻

一个中文、手机优先的 AI 饮食记录 Web App。拍照识别食物与份量并给出营养区间，有可靠数据库或参考配方时优先查库；缺库时使用带假设的 AI 估算。糖、用油等提供三个参考情景，默认普通档，以区间中值记账；也可以输入确定数值。饮食、个人估算食物库、体重和目标保存在当前浏览器的 IndexedDB 中。

## 本地运行

需要 Node.js 24 LTS 或更新的受支持版本、npm。

```powershell
npm install
# 已有 .env 时不要覆盖；仅首次配置执行下面一行。
Copy-Item .env.example .env
npm run dev
```

打开 <http://127.0.0.1:5180>。前端通过 Vite 代理访问本机 3001 端口的后端。未配置所选模型的密钥时，默认进入明确标识的 Mock 模式，仍可完整测试识别、编辑与保存。

本项目的 npm 缓存位于 `.npm-cache`，不会修改系统 npm 设置。首次安装需要访问 npm 官方仓库。

### 手机查看

电脑与手机连接同一 Wi-Fi，先停止原来的开发服务，再运行 `npm run dev:lan`。等前后端启动后，在手机系统浏览器打开终端打印的局域网地址（例如 `http://192.168.1.10:5180/`）。命令自动配置本次运行的精确页面来源，后端仍只监听电脑本机，不修改 `.env`。普通 `npm run dev` 保持仅本机访问。

手机与电脑的数据各自保存在当前浏览器，不会自动同步；可用 JSON 备份迁移。网卡选择、防火墙和相机入口说明见 [手机联调教学](docs/mobile-testing.md)。

## 配置 AI

根目录 `.env` **只由服务端读取**。不要给密钥添加 `VITE_` 前缀，不要在前端代码、截图、Git 提交或教学笔记中写入真实密钥。

```dotenv
AI_PROVIDER=gemini
AI_MODE=auto
GEMINI_API_KEY=在本机填入你的密钥
ZHIPU_API_KEY=
```

开发默认模型为 `gemini-3.5-flash-lite`，使用 Free Tier 项目的密钥。模型有免费层级并不代表任何项目都免费：已开启计费的项目按其计费规则收费，实际额度请在 Google AI Studio 查看。应用不会开通计费，也不会自动切换付费模型。

切换智谱：将 `AI_PROVIDER` 改为 `glm`，配置 `ZHIPU_API_KEY`，重启后端。模型固定为 `glm-4.6v-flash`，使用普通 API，不使用 Coding Plan 的套餐端点。

`AI_MODE=mock` 强制模拟；`auto` 缺少所选模型密钥时模拟；`live` 要求密钥存在。真实调用失败会显示错误，不能把模拟结果冒充真实识别。模拟记录保存后仍带有标识，当日汇总也会提示。

2026-10-14 的最小调用测试中，Gemini 的视觉、非食物拒识和结构化输出均成功；GLM 两次返回 429/1305 服务过载。这些结果不是餐食重量准确率承诺。

详见 [AI 模型调用教学](docs/ai-models.md) 和 [完整开发教学](docs/development-guide.md)。

## 使用与数据

- 饮食页可以拍照、上传、手动记录，修改食物名称、可食重量和每 100 g 营养值，再选择日期及餐次保存。点击“选择食物”打开食物库弹窗：**5,675 条食物参考 + 60 个可调配方**按类浏览。其中 472 条来自 USDA SR Legacy，5,203 条来自 USDA FNDDS 2021–2023，覆盖更多面食、点心、熟食、汤粥、饮品和零食，含不同做法与配料版本，不等于这么多种独立中国菜。支持中文名称、别名、原文和配料搜索，部分专名保留英文；列表每次显示 60 项。顶部本地推荐与识别名称和可见配料相近的食物，不增加 AI 请求，点击候选后才更换记录。照片识别与 AI 营养粗估合并为一次模型请求。
- 计算顺序为基础食物／参考配方、已确认的个人估算条目、本次 AI 粗估。无依据时仍显示待补充，不把未知当零。AI 不确定名称时仍拒绝编造食物。
- 默认浏览熟食和即食食物，隐藏生肉、生蛋及待烹调干料；水果、生菜和黄瓜保留。可勾选“包含生重／干重食材”查看全部，已保存的生重记录不受影响。
- 一张照片可返回多种食物，逐项自动匹配食物库／参考配方，并带入各自的可食重量；总览可查看所有项并跳到对应编辑卡片。“一碗米饭”等量词可在本地简化后匹配，不额外请求模型。混合菜不再重复累计其可见配料；无法可靠估重时留空，可手动填写，确认后一起保存。
- 热量、营养、重量、区间及输入框最多显示两位小数，不补尾零。内部计算和历史快照保留完整精度，用户主动输入的确定值最多两位。
- 旧个人库只有单值，或其普通档缺少热量时，本次识别提供的有效热量三档会优先采用。确认保存后升级原库条目并保留 ID；旧餐食仍使用原来的数值快照。不会给旧单值凭空补出范围。
- 新 AI 估算提供低／中／高三档，按食物显示甜度与稀稠、用油或一般情景。默认中档，再取该档区间的算术中值。参考配方的油档在原配料中替换油量，不另加一份油。确定的包装营养值或实际配料可手填，替代这一条范围估算。
- 区间统一按每 100 g 保存，按食物重量换算整份。例如参考粥普通档 60～90 kcal/100 g，300 g 的区间为 180～270 kcal，记账中值为 225 kcal。这是应用参考情景，不是所有粥的标准，更不是模型测量精度。历史保存当时的档位；下一次新识别同名食物重新默认普通档。
- 真实识别的 AI 缺库条目只有在确认保存后，才与餐食一同写入个人估算库；未保存的草稿和 Mock 数据不会污染这份库。库里的数值始终标注估算，不会加入 USDA 数据或共享给别人。
- 体重页每天记录一次体重，支持修改、删除和设置目标。
- 设置页支持 JSON 导出与完整恢复。版本 2 备份包含个人估算库，原版本 1 备份可自动升级导入。恢复前校验并显示记录数量，确认后事务性替换。
- 浏览器清理、隐私模式、换设备、换浏览器或换网址会影响本地数据。`127.0.0.1` 与 `localhost`、不同端口也是不同存储空间；定期导出备份。
- 图片只用于本次识别，应用不把照片保存进 IndexedDB、上传目录或日志。Gemini 使用内联图片及 `store:false`；免费服务仍可能用输入和输出改进 Google 产品。

基础营养数据来自 [USDA FoodData Central](https://fdc.nal.usda.gov/)，其数据为公共领域／CC0。中文名称为应用整理的别名，参考配方为食刻的计算假设，不能视为中国标准菜品数据。AI 补充的数值只是根据常见做法的粗估：合法范围检查不代表真实准确，粥的含水量、用糖和用油等差异需确认。来源及换算规则见 [营养数据说明](docs/nutrition-data.md)。无法粗估的数据仍保留为空，汇总显示已知部分。

## 验证与生产运行

```powershell
npm run typecheck
npm test
npm run build
npm run test:e2e
npm start
```

生产运行由同一个 Node.js 服务提供网页和 `/api`，默认 <http://127.0.0.1:3001>。基础浏览器测试使用本机 Chrome、Edge，无需先下载 Chromium；E2E 使用独立端口及 Mock 模式，不会消耗真实模型额度。

真实手机测试需要手机能够访问运行前端的电脑。可信局域网可用 `npm run dev -w @shike/web -- --host 0.0.0.0`，并在服务端 `.env` 中设置 `PUBLIC_ORIGIN=http://电脑局域网IP:5180` 后重启，通过该 IP 的 5180 端口访问。公网使用必须配置 HTTPS。iOS 的 HEIC 等浏览器无法解码的格式需先转换为 JPEG；拍照入口使用系统文件选择器，不依赖持续摄像头权限。

本次已执行验证：140 项单元／接口测试、33 个 Chrome 手机视口／Chrome 桌面／Edge 桌面 E2E 场景、类型检查与生产构建均通过。场景覆盖三档切换与中值、份量缩放、确定数覆盖、配方油量只计算一次、旧单值个人库升级、历史快照及备份恢复，以及食物弹窗的分类搜索、相近推荐、取消返回、焦点恢复和更换后保存。新增验证五千条以上食物的分批浏览、中文搜索和 FNDDS 记录保存刷新；另外直接对照官方 JSON，5,203 条新增食物的 20,812 个营养字段全部一致。此前前端构建产物扫描未发现本机 API Key；此前真实 Gemini 对公开餐食样图返回了四项食物的完整三档及假设，HTTP 200，并通过本地校验，服务端还纠正了模型单值与区间中值不一致的情况。多食物流程另做一次公开样图的 Gemini 真实调用，约 9.6 秒返回四项食物及四个独立估重，三项可匹配当时已有基础食物／参考配方；本轮扩库不额外调用模型，浏览器测试使用隔离 Mock，不发送私人照片。没有称重及营养真值对照，不能据此认定估算准确。界面截图见 `docs/screenshots`。手机真机相机和有称重真值的准确率测试仍待后续实测。

## 后续部署

第一版面向本地运行。未来可部署到提供 Node.js 的服务器或容器，由 HTTPS 反向代理提供同源访问。密钥放在平台环境变量；前端静态构建和服务端一起部署。免费托管能否持续免费、地域连通性、休眠和请求额度需在部署时重新核实。

公网分享前需要共享访问保护、持久化且跨实例一致的全局额度、正确的可信代理配置和精确 Origin 策略。本地内存限频会随重启清空，不作为公网成本上限保证。此工作区的初始本地 Git 历史曾包含旧智谱密钥；现已重写本地历史并清除旧恢复记录及敏感对象，项目文件和本机环境配置保留。Git 清理不会撤销密钥，旧密钥仍须在智谱控制台撤销并换新；如果之前复制过旧仓库，还需处理那些副本。[密钥清理原则](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)

本版没有账号、收费和云同步。图片份量、混合菜的油与酱汁都可能有较大误差，所有热量为估算值。
